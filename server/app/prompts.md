# Prompt enhancement

Image prompt enhancement keeps its existing structured output contract. Video prompt enhancement uses the same vLLM request helper with `temperature=0.3`, but asks for one strict JSON object with `shots`, `overall_soundscape`, `non_diegetic_music`, and overall `negative`. Every `shots[]` object has `start_ms`, `style`, `timeline`, `camera`, `audio`, and `text`; server directly assembles the editable final prompt without output revalidation. String fields supply a dynamic character pattern and bounded repetition for the selected `ko`, `en`, and `ja` output languages, while only exact server-owned structural tokens are allowed outside that set. Digits, ASCII punctuation, spaces, and line breaks are always part of the allowed set. Every string is one concise sentence; `negative` is one short overall sentence with no repeated or exhaustive list. vLLM output requests allow up to 10 minutes; the image and video enhancement UI requests use the same 10-minute limit.

The video system prompt returns only shot data; server owns `[Shot N]`, `At MM:SS.mmm`, final section order, and overall negative assembly. Reference roles are added by the server after enhancement so the labels match the actual I2V, FL2V, or R2V inputs. Long video enhancement sends the one user-entered overall prompt for every duration-derived segment with segment number, segment duration, and prior scene context. vLLM distributes the overall intent across segments while every shot uses its own local segment clock, never a global sequence timestamp. Segment 2 onward is R2V and `<Picture 1>` means the actual final frame from the prior generated segment. vLLM returns reviewable proposals only; it never writes user scene prompts.
