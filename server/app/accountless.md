# 계정 없는 공용 데이터 전환

서버 시작 시 기존 콘텐츠를 유지하면서 계정 의존성을 제거한다. 계정·인증 이력 테이블과 콘텐츠·API 로그·웹 로그의 user_id 열을 삭제한다. 로그인·회원가입 API 기록과 로그인 화면의 웹 이벤트도 제거한다. 신규 스키마에는 계정 테이블과 소유자 필드를 생성하지 않는다.

이미지·영상·음악·3D 결과, 업로드, 프리셋, 저장 프롬프트와 다운로드 이력은 공용으로 유지한다. 같은 타입에 기본 프리셋이 여러 개 있으면 가장 최근에 수정한 기본값 한 개만 유지하며 다른 프리셋 자체는 삭제하지 않는다. 동일 출처·원본의 활성 다운로드가 중복되면 가장 먼저 생성한 작업을 유지하고 나머지는 cancelled로 남긴다.

다운로드 토큰은 provider별 최신 값을 선택하고 계정 식별자 없이 다시 암호화해 저장한다. 복호화 실패 시 트랜잭션을 실패시켜 기존 계정·콘텐츠·토큰을 부분적으로 지우지 않는다. 주 DB와 웹 로그 DB는 각각 한 트랜잭션으로 적용하며 재실행해도 같은 결과가 된다.

외부 스토리지가 과거 파일 접근에 요구하는 불투명한 owner 값을 storage_file_owners에 파일별로 보존한다. 이름·비밀번호·로그인 토큰은 보존하지 않으며 이 매핑은 접근 제어나 사용자별 조회에 쓰지 않는다. 새 파일은 local-field 공용 소유 값을 사용한다. 외부 스토리지 데이터 자체를 삭제하거나 이동하지 않는다.
