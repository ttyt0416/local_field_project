# 파일 관리

`/files`는 Civitai 다운로드와 분리된 모델 스토리지 탐색기다. 공용 Layout과 사이드바를 사용하며 로그인 후 `GET /models/installed`와 여섯 모델 종류의 `GET /models/folders`를 읽는다. 내 스토리지의 사용량은 설치 파일의 실제 합계이며 디스크 전체 용량이나 임의 할당량을 표시하지 않는다.

다운로드 진입 링크와 빈 폴더 안내는 `/models`의 다운로드 관리로 연결한다. Civitai와 Hugging Face에서 받은 파일은 동일한 스토리지에 표시하며 GGUF도 모델 파일로 관리한다.

루트는 체크포인트·Diffusion Model·LoRA·텍스트 인코더·VAE·임베딩을 독립 폴더로 표시한다. 하위 폴더에 들어가면 바로 아래 폴더와 파일을 표시하며 breadcrumb로 상위 위치로 이동한다. 빈 폴더도 폴더 API 응답으로 유지한다. 검색은 현재 위치 아래 전체 파일과 폴더에 적용하고 이름순·최근 수정순·용량순 정렬 및 목록·격자 보기를 제공한다. 폴더는 파일보다 먼저 표시하고 폴더 용량과 파일 개수는 하위 파일 전체의 합계다. 폴더의 수정 일자는 추측하지 않는다. 선택한 파일은 별도 정보 패널에서 이름·종류·크기·경로·수정일을 확인한다.

새 폴더는 `POST /models/folders`를 사용한다. 루트에서 만들 때는 모델 종류를 선택하며 하위 위치에서는 현재 경로를 사용한다. 파일 이동은 공용 ModelFolderPicker로 같은 모델 종류 안의 목적지를 선택하고 `POST /models/installed/{model_type}/move`에 원본 filename과 목적지 subfolder를 보낸다. 이동 후 파일·폴더 목록을 새로 읽는다. 삭제는 확인 모달 후 원래 상대 경로를 segment별 인코딩해 `DELETE /models/installed/{model_type}/{filename}`을 호출한다. 파일의 모델 종류를 바꾸거나 실제 파일을 임의 이동·삭제하는 초기화는 수행하지 않는다.

API 오류는 Toast로 표시하고 초기 읽기 실패 시 재시도를 제공한다. 비동기 작업 중 버튼의 loading·disabled 상태를 표시한다. 페이지를 떠난 뒤 늦게 도착한 응답은 적용하지 않는다. 클릭과 경로 이동은 루트 layout의 기존 이벤트 로깅을 사용한다.

목록·격자의 하위 폴더와 현재 폴더 경로에 폴더명 변경·폴더 전체 삭제 버튼을 표시한다. 모델 종류의 기본 폴더에는 해당 작업을 제공하지 않는다. 이름 변경은 `POST /models/folders/{model_type}/rename`으로 처리하고 하위 폴더·파일과 현재 탐색 경로를 새 prefix로 갱신한 뒤 목록을 재조회한다.

폴더 삭제 확인창은 `GET /models/folders/info`에서 모델 외 파일까지 포함한 정확한 파일 수·하위 폴더 수·용량을 읽는다. 다운로드가 대기·진행 중이면 확인 버튼을 막고 다시 확인을 제공한다. 확인한 revision을 DELETE query로 보내며 서버에서 내용 변경을 감지하거나 삭제에 실패하면 다시 확인하기 전까지 삭제 버튼을 막는다. 삭제 완료 시 하위 항목을 목록에서 제거하고 삭제한 경로 안에 있으면 상위 폴더로 돌아간다. 실제 삭제는 확인 버튼을 누른 뒤에만 실행한다.
