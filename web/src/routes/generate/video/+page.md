# MiniMax H3 동영상 생성 화면

I2V·FL2V·R2V를 tab으로 선택한다. 각 input은 device storage 또는 stored content selection modal에서 선택한다. existing file은 `file_id`로 전송해 owner check 뒤 재사용하고 local file은 generation submit 때만 multipart로 전송한다.

동영상 생성의 image source selector는 `저장된 콘텐츠 → 생성 → T2I (Anima)`를 initial state로 열고, `ANIMA`, `ILLUSTRIOUS`, `KREA2` family tab과 그 아래 `T2I`, `I2I` mode tab을 표시한다. selected category는 `/uploads`의 `generation_mode`와 `model_family` exact filter로 전송한다. video/audio reference는 image generation category filter 없이 기존 device selection을 유지한다.

I2V·FL2V·R2V source card는 12rem preview만 제공한다. Ref image/video/audio는 conditioning input이며 original media dimensions를 읽거나 output size에 적용하지 않는다. output은 user가 선택한 `2:3`, `3:2`, `1:1`, `16:9`, `9:16` ratio와 Base MP input으로 결정되며 initial value는 `1:1`과 `0.1 MP`다. Base와 learned 3D latent Target MP는 모두 32 pixel width/height H3 patch grid preview를 표시한다. Base와 Target MP는 한 자리 반올림 뒤 server와 same grid calculation으로 integer preview를 표시하며, direct resolution input은 없다.

`Checkpoint`는 current video mode의 `/generation/video/options` 결과를 folder-filtered modal로 표시한다. Eros와 Dasiwa MiniMax H3 int8만 남고 Dasiwa가 default다. `MiniMax/` allowlist의 LoRA를 folder-filtered modal에서 multi-select하며, 선택 순서와 strength를 request에 기록한다. Checkpoint와 LoRA block 사이는 settings form의 existing section spacing으로 구분한다. normal mode는 IMAGE GEN과 같은 공용 live ComfyUI sampler/scheduler choice modal을 제공하고 selected values를 request, preset, Vault detail/preset 저장에 남긴다. `PDD 사용`은 live PDD node와 matching LoRA가 있을 때만 활성화되고, 켜면 PDD schedule의 Euler sampler와 matching Ref2VA PDD file을 사용하므로 sampler/scheduler selection은 disabled다. Steps input은 request·preset에 저장되며 PDD는 4·6·8 step만 전송한다. 두 column의 video result/settings layout은 `min-w-0`과 `max-w-full`로 side column 내에서 shrink하며 header controls가 wrap되므로 small viewport에서 horizontal overflow를 만들지 않는다.

스타일·전체 배경 input 하나와 duration에서 계산한 시간 구간별 scene input을 분리한다. 예를 들어 30초 영상은 `0~10초`, `10~20초`, `20~30초` 구간을 각각 입력하며, 각 구간은 최소 하나의 `장면 N` textarea를 가진다. 구간 header의 icon-only `+` button은 scene을 추가하고 각 scene의 icon-only delete button은 해당 scene을 삭제한다. 마지막 하나의 scene은 삭제할 수 없다. duration 변경은 scene list와 improved value를 array에 유지하고 현재 time range의 index만 화면에 표시한다. transient `0` duration도 state를 축소하지 않는다. 생성 request 직전에만 current time range 밖의 scene list와 improved value를 array에서 제거한다. 각 구간의 scenes는 순서대로 `[Scene N]` block 한 string으로 serialize하여 기존 `segment_prompt` and `segment_prompts` API contract로 전송하므로 prompt enhancement and direct generation 모두 scene 경계와 순서를 받는다. `전체 프롬프트 개선`은 browser가 공통 context와 모든 현재 구간 scenes를 vLLM으로 하나씩 직렬 전송하고, 각 구간의 `프롬프트 개선` button은 해당 구간만 요청한다. 화면은 raw scenes 다음에 해당 구간의 개선 프롬프트를 표시하며, 전체 style/background 수정은 all improved values를 reset하고 scene 추가·수정·삭제는 그 구간 improved value만 reset한다. 각 block의 timeline clock은 global video time이 아니라 해당 segment의 `0초`부터 segment duration까지다. 예를 들어 11초 영상의 두 번째 block은 `0~1초`다. 10초 초과 sequence에서는 final frame 연결을 R2V 또는 I2V로 선택한다. R2V는 final frame을 Picture 1로 사용하고 selected image references는 Picture 2부터 유지하며 선택 image는 최대 8개다. I2V는 final frame을 next segment의 first frame으로 쓴다. 생성은 prompt 개선을 끈 경우 공통 context와 serialized scenes를, 켠 경우 사용자가 submit한 segment별 proposal을 사용한다. result status에는 active `구간 n/N`과 sequence aggregate progress를 표시한다.
